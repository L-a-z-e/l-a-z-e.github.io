알고리즘 문제를 해결하기 위해 그래프 탐색 기법인 BFS(너비 우선 탐색)와 DFS(깊이 우선 탐색)를 학습하며, 이를 코드로 구현하고 동작 원리를 검증했다. 이 과정에서 그래프의 기본 표현 방식부터 각 탐색 알고리즘의 특성과 구현상의 차이점을 논리적으로 정리해 보았다.

**그래프 표현 방식의 비교: 인접 행렬과 인접 리스트**

그래프를 데이터로 구조화할 때 주로 인접 행렬과 인접 리스트 두 가지 방식을 고려한다. 인접 행렬은 2차원 배열을 사용하여 노드 간의 연결 상태를 표시하는 방식이다. 반면, 인접 리스트는 각 노드마다 자신과 직접 연결된 노드의 목록만을 저장한다.

| 비교 항목 | 인접 행렬 (Adjacency Matrix) | 인접 리스트 (Adjacency List) |
| :--- | :--- | :--- |
| **구조** | 2차원 배열 | 리스트의 배열 또는 리스트 내의 리스트 |
| **메모리 사용** | 연결되지 않은 노드의 관계까지 모두 저장하여 비효율적 | 연결된 간선 정보만 저장하여 메모리 효율적 |
| **실무 및 알고리즘 적용** | 제한적인 상황에서 사용됨 | 대부분의 그래프 문제에서 기본 구조로 채택됨 |

실제 알고리즘 테스트나 실무 환경에서는 메모리 효율성을 고려하여 인접 리스트 방식을 주로 사용한다. 자바(Java)를 기준으로 동적 배열인 `ArrayList`와 `Scanner`를 활용하여 양방향 간선을 가진 그래프를 초기화하는 구조는 다음과 같다.

```java
Scanner sc = new Scanner(System.in);
int n = sc.nextInt(); // 노드 수
int e = sc.nextInt(); // 간선 수

List<List<Integer>> graph = new ArrayList<>();
// 노드 수만큼 내부 리스트 초기화
for (int i = 0; i < n; i++) {
    graph.add(new ArrayList<>());
}

// 간선 정보 입력 및 양방향 연결
for (int i = 0; i < e; i++) {
    int a = sc.nextInt();
    int b = sc.nextInt();
    graph.get(a).add(b);
    graph.get(b).add(a); 
}
```

**BFS의 큐(Queue) 활용과 최단 경로 보장**

그래프 구조가 준비된 후 BFS를 구현했다. BFS는 시작 노드에서 가까운 거리의 노드부터 순차적으로 탐색을 진행한다. 이 특성 때문에 최단 경로를 찾는 문제에 적합하다.

BFS가 최단 경로를 보장하는 핵심 원리는 자료구조 큐(Queue)의 FIFO(First-In-First-Out) 특성에 있다. 탐색을 시작하면 거리가 1인 노드들이 먼저 큐에 들어가고 순서대로 처리된다. 물리적으로 거리가 1인 노드들을 전부 처리하기 전에는 큐의 구조상 거리가 2인 노드를 꺼낼 수 없다. 따라서 특정 노드에 처음 도달한 순간이 그 노드까지의 최단 거리임이 성립한다.

구현 시 주의해야 할 부분은 방문 여부(`visited`)를 기록하는 시점이다. 큐에서 노드를 꺼낼 때 방문 처리를 하게 되면, 동일한 노드가 큐에 중복으로 삽입되는 문제가 발생할 수 있다. 이를 방지하기 위해 큐에 노드를 삽입하기 직전에 방문 처리를 완료해야 한다.

```java
static void bfs(int start) {
    boolean[] visited = new boolean[4];
    Queue<Integer> queue = new ArrayDeque<>(); // 인터페이스 Queue의 구현체로 ArrayDeque 사용
    
    visited[start] = true; // 큐에 넣기 전 시작 노드 방문 처리
    queue.add(start);
    
    while (!queue.isEmpty()) { // 큐가 빌 때까지 반복
        int current = queue.poll();
        System.out.print(current + " ");
        
        for (int neighbor : graph.get(current)) {
            if (!visited[neighbor]) {
                visited[neighbor] = true; // 삽입 전 방문 처리로 중복 방지
                queue.add(neighbor);
            }
        }
    }
}
```

**DFS의 동작 방식: 재귀(Recursion)와 스택(Stack)**

BFS가 층별로 탐색을 진행한다면, DFS는 한 방향으로 더 이상 갈 수 없을 때까지 깊게 탐색한다. DFS는 스택(Stack)을 사용하거나 재귀 함수를 통해 구현한다. 처음에는 스택이나 단순 반복문을 고려했으나, 코드의 간결성과 이후 백트래킹(Backtracking) 로직을 제어하기에는 재귀를 활용하는 방식이 보편적이며 구조적으로 깔끔하다는 것을 확인했다.

재귀를 이용한 DFS는 함수 호출 자체가 시스템 스택을 이용한다. 현재 노드를 방문 처리하고, 연결된 이웃 노드 중 방문하지 않은 노드가 있다면 해당 노드를 시작점으로 다시 DFS 함수를 호출한다. 더 이상 탐색할 연결 노드가 없으면 이전 호출 지점으로 자동 복귀한다.

```java
static void dfs(int current, boolean[] visited) {
    visited[current] = true;
    System.out.print(current + " ");
    
    for (int neighbor : graph.get(current)) {
        if (!visited[neighbor]) {
            dfs(neighbor, visited); // 이웃 노드로 재귀 진입
        }
    }
    // 더 이상 탐색할 이웃이 없으면 이전 호출 지점으로 복귀
}
```

만약 재귀가 아닌 자료구조 스택(`Deque`)을 직접 선언하여 DFS를 구현한다면 방문 체크 시점이 BFS와 달라진다. 큐를 사용하는 BFS는 삽입 시점에 방문을 체크하지만, 스택을 사용하는 DFS는 노드를 넣을 때 체크하면 재귀 방식과 탐색 순서가 달라지므로, 스택에서 `pop()`으로 꺼낸 시점에 방문 여부를 확인하고 처리해야 한다.

결과적으로 그래프 데이터를 바탕으로 목적지까지의 최단 거리를 구해야 한다면 큐를 활용한 BFS 구조를 채택하고, 특정 경로를 끝까지 탐색하거나 탐색 과정에서 백트래킹이 필요하다면 재귀 기반의 DFS 구조를 채택하는 것이 타당한 기술적 결정이다.
