알고리즘 문제 해결 시 DP(Dynamic Programming)와 Greedy 알고리즘 중 어떤 방식을 선택해야 하는지 판단하는 기준을 정립하기 위해 두 개념의 핵심 원리를 재검증했다.

초기에는 DP를 점화식을 세워 값을 하나씩 채워나가는 방식, Greedy를 가장 큰 것부터 선택하고 안 되면 작은 것을 시도하는 방식으로 인지하고 있었다. 하지만 이는 각 알고리즘의 본질적인 동작 원리를 누락한 불완전한 이해였다.

Greedy 알고리즘의 핵심은 매 순간 최선을 선택하고 이를 번복하지 않는 데 있다. 단순히 가장 큰 것을 고르는 것이 아니라, 현재의 최우선 선택이 전체의 최적해에 포함된다는 전제가 보장될 때만 유효하다. 반면 DP의 본질은 중복 계산의 제거다. 단순 재귀로 접근할 경우 동일한 연산이 수십억 번 반복될 수 있으나, DP는 한 번 계산한 결과를 테이블에 저장해두고 필요할 때 재사용하여 연산량을 획기적으로 줄인다.

이러한 판단 기준을 배낭 문제(Knapsack Problem)에 적용하여 Greedy의 한계를 확인했다. 배낭 문제는 제한된 무게 안에서 가치 합계를 최대화하는 최적화 문제다. 이 문제에 Greedy를 적용하여 가치가 높은 물건부터 우선적으로 담을 경우, 무게가 큰 물건이 배낭의 용량을 조기에 차지하게 된다. 결과적으로 더 작은 가치의 물건 여러 개를 조합하여 총 가치를 높일 수 있는 경우의 수를 놓치게 된다. 즉, 현재 가치가 가장 높은 것을 선택하는 단기적 최선이 전체의 최적해를 보장하지 못한다.

이를 구체적인 반례 데이터를 통해 검증한 결과는 다음과 같다. 배낭의 무게 한도가 5kg일 때의 상황이다.

| 조건 / 알고리즘 | 물건 선택 | 총 무게 | 총 가치 | 판단 결과 |
| :--- | :--- | :--- | :--- | :--- |
| **주어진 물건** | A (4kg, 5만원), B (3kg, 4만원), C (2kg, 3만원) | - | - | - |
| **Greedy 접근** | A 선택 (가치 우선) → 남은 용량 1kg로 B, C 담기 불가 | 4kg | 5만원 | 오답 (최적해 도출 실패) |
| **DP 접근 (최적해)** | B + C 선택 | 5kg | 7만원 | 정답 |

Greedy로 접근할 경우 2만원의 손실이 발생함을 확인했다. 따라서 매 순간의 선택이 이후의 상태에 영향을 미치고 모든 조합을 고려해야 하는 배낭 문제에는 DP를 적용해야 한다.

DP를 활용하기 위해 먼저 상태를 정의했다. `dp[i][w]`를 'i번째 물건까지 고려했을 때, 무게 w 이하에서 얻을 수 있는 최대 가치'로 설정했다. 이후 각 물건을 배낭에 담지 않는 경우와 담는 경우로 나누어 점화식을 도출했다.

물건을 담지 않는다면 이전 물건까지의 최적해인 `dp[i-1][w]`를 그대로 가져온다. 반면 물건을 담는다면, 해당 물건의 무게만큼 뺀 나머지 용량에서 이전까지의 최적해를 구하고 현재 물건의 가치를 더한다. 즉, `dp[i-1][w - weight[i]] + value[i]`가 된다. 이 두 가지 경우 중 더 큰 값을 현재의 상태 값으로 갱신한다.

```java
// dp[i][w] = i번 물건까지, 무게 w 한도에서 최대 가치
int[][] dp = new int[n+1][W+1];

for (int i = 1; i <= n; i++) {
    for (int w = 0; w <= W; w++) {
        // i번 물건을 안 담는 경우 (이전 결과 그대로)
        dp[i][w] = dp[i-1][w];
        
        // i번 물건을 담는 경우 (무게가 허용될 때만)
        if (w >= weight[i]) {
            dp[i][w] = Math.max(
                dp[i][w],
                dp[i-1][w - weight[i]] + value[i]
            );
        }
    }
}
```

이 코드는 이전에 계산된 `dp[i-1]` 행 전체가 테이블에 저장되어 있으므로, 불필요한 중복 계산 없이 각 상태를 확정해 나간다.

결론적으로 배낭 문제와 같이 하위 문제의 결과가 상위 문제에 영향을 미치는 경우, 두 알고리즘의 적용 결과는 아래와 같은 트레이드오프를 가진다.

| 알고리즘 | 시간 복잡도 | 최적해 보장 여부 (배낭 문제 기준) | 특징 |
| :--- | :--- | :--- | :--- |
| **Greedy** | O(N log N) | 불가 (항상 최적해를 보장하지 않음) | 매 순간의 최선만 고려. 전체 해답 검증 불가 |
| **DP** | O(N × W) | 가능 (항상 최적해 도출) | 이전 계산 결과를 저장하여 중복 연산 방지 |

DP는 탐색 과정에서 O(N × W)의 시간 복잡도를 가지지만 주어진 제한 조건 내에서 항상 최적해를 찾아낸다. 따라서 "지금 최선의 선택이 전체 최적에 포함되는가"라는 질문에 "그렇다"고 증명할 수 없을 때, DP를 설계하여 접근하는 것이 타당한 판단 기준임을 확인했다.
