정렬 알고리즘의 동작 원리와 시간 복잡도에 대해 학습하며, 단순 비교 연산의 한계부터 각 알고리즘이 불필요한 비교를 줄이는 방식을 정리했다. 4개의 원소 `[5, 3, 8, 1]`을 정렬할 때 모든 쌍을 비교하는 방식을 취하면 $N \times (N-1)/2$번의 연산이 발생하여 $O(N^2)$의 시간 복잡도를 가진다. 원소가 100만 개라면 5,000억 번의 비교가 필요하다. 따라서 정렬 과정에서 비교 횟수를 줄이는 것이 핵심이며, Quick, Merge, Heap Sort는 각기 다른 방식으로 이를 해결하여 $O(N \log N)$의 복잡도를 달성한다.

### 불필요한 비교를 차단하는 Quick Sort
Quick Sort는 기준점(Pivot)을 사용하여 비교 횟수를 줄인다. Pivot을 정하고 이를 기준으로 작은 값은 왼쪽, 큰 값은 오른쪽으로 분리한다. Pivot이 자기 자리를 찾아 확정되면, 분할된 왼쪽과 오른쪽 구간은 서로 다시 비교할 필요가 없으므로 전체 연산이 감소한다.

```text
입력: [5, 3, 8, 1, 9, 2, 7]
partition: pivot=7 → [5, 3, 1, 2, | 7 | 8, 9]  ← 7 기준으로 좌우 분리
partition: pivot=2 → [1, 2, | 5, 3, ...        ← 왼쪽 구간 재귀
partition: pivot=3 → [1, 2, 3, 5, ...          ← 계속 재귀
partition: pivot=9 → 오른쪽 구간 [8,9] 처리
결과: [1, 2, 3, 5, 7, 8, 9]
```

시간 복잡도의 논리적 도출 과정은 트리의 깊이(레벨)와 각 레벨의 비교 횟수로 설명된다. 데이터를 반씩 분할하는 이상적인 경우 트리의 레벨은 $\log N$이 되고, 각 레벨에서의 총 비교 횟수는 $N$이므로 전체 복잡도는 $O(N \log N)$이 된다. 하지만 Pivot이 지속적으로 한쪽으로 편향되게 선택될 경우, 분할되는 트리의 깊이가 $\log N$이 아닌 $N$이 되어 최악의 경우 $O(N^2)$으로 회귀한다.

### 배열 인덱스와 완전 이진 트리를 활용한 Heap Sort
Heap Sort는 Max-Heap 구조의 특성을 활용한다. 배열을 완전 이진 트리로 간주하며, 별도의 구조체 없이 인덱스 계산만으로 부모와 자식 노드를 특정할 수 있다. 인덱스 $i$의 노드에 대해 왼쪽 자식은 $2i+1$, 오른쪽 자식은 $2i+2$, 부모는 $(i-1)/2$의 위치를 가진다.

```text
입력: [5, 3, 8, 1, 9, 2, 7]
heapify 완료: [9, 5, 8, 1, 3, 2, 7]  ← 9가 루트(최댓값)
루트 추출 후: [8, 5, 7, 1, 3, 2, | 9]  ← 9 확정, 8이 새 루트
루트 추출 후: [7, 5, 2, 1, 3, | 8, 9]  ← 8 확정
루트 추출 후: [5, 3, 2, 1, | 7, 8, 9]  ← 7 확정
결과: [1, 2, 3, 5, 7, 8, 9]
```

루트 노드가 항상 최댓값이라는 성질을 이용하여 루트를 추출하고 배열의 맨 뒤로 보낸다. 추출 후 트리를 재정렬(heapify)하는 비용은 $O(\log N)$이며, 이를 $N$번 반복하므로 $O(N \log N)$이 도출된다. 이 방식은 매번 최댓값을 맨 뒤로 보내며 뒤에서부터 정렬을 확정 짓는다.

### 정렬된 상태를 활용한 Merge Sort와 비교 횟수 증명
Merge Sort는 원소가 1개인 상태는 이미 정렬된 상태라는 점을 전제로 한다. 배열을 더 이상 나눌 수 없을 때까지 쪼갠 후, 두 포인터를 활용하여 $O(N)$의 비용으로 병합을 진행한다.

```text
입력: [5, 3, 8, 1, 9, 2, 7]
merge [0~1]: [3, 5, ...]     ← [5]와 [3] 합치기: 3<5 → [3,5]
merge [2~3]: [..., 1, 8, ... ← [8]와 [1] 합치기: 1<8 → [1,8]
merge [0~3]: [1, 3, 5, 8,... ← [3,5]와 [1,8] 합치기
merge [4~5]: [..., 2, 9, ... ← [9]와 [2] 합치기
merge [4~6]: [..., 2, 7, 9]  ← [2,9]와 [7] 합치기
merge [0~6]: [1,2,3,5,7,8,9] ← 전체 합치기
```

초기 학습 단계에서 `[1, 3]`과 `[5, 7]`을 병합할 때 각 원소를 모두 대조하여 총 4번(1-5, 1-7, 3-5, 3-7)의 비교가 발생한다고 오해했다. 그러나 병합 과정의 핵심은 두 배열이 '이미 정렬되어 있다'는 사실을 활용하여 불필요한 비교를 건너뛰는 데 있다.

실제 병합 과정을 추적하여 이를 확인했다.

1.  **1단계:** 배열 A의 1과 배열 B의 5를 비교한다. $1 < 5$이므로 1을 결과 배열에 넣고, 배열 A의 포인터를 다음으로 이동한다.
2.  **2단계:** 배열 A의 3과 배열 B의 5를 비교한다. $3 < 5$이므로 3을 결과 배열에 넣는다.
3.  **3단계:** 배열 A가 소진되었다. 남은 배열 B의 원소 `[5, 7]`은 이미 정렬된 상태이므로 추가 비교 없이 결과 배열에 복사한다.

$1 < 5$가 확정된 순간, 5와 7은 이미 정렬되어 있으므로 1과 7을 비교할 필요가 없다는 논리가 성립한다. 결과적으로 4개의 원소를 합칠 때 최대 비교 횟수는 $N-1$인 3번으로 제한된다. 이러한 방식으로 각 병합 단계마다 비교 횟수를 $N$에 수렴하게 만들며, 병합을 위한 임시 배열 공간으로 인해 $O(N)$의 추가 공간 복잡도가 발생한다.

### 정렬 알고리즘 Trade-off 비교 분석
도출된 각 알고리즘의 동작 원리와 복잡도를 기반으로 특징을 정리했다.

| 알고리즘 | 시간 복잡도 (평균) | 시간 복잡도 (최악) | 공간 복잡도 | 핵심 동작 원리 및 특징 |
| :--- | :--- | :--- | :--- | :--- |
| **Quick Sort** | $O(N \log N)$ | $O(N^2)$ | $O(\log N)$ | Pivot을 기준으로 좌우 분할. 자리가 확정된 Pivot은 재비교하지 않음. Pivot 편향 시 $O(N^2)$ 발생. |
| **Merge Sort** | $O(N \log N)$ | $O(N \log N)$ | $O(N)$ | 이미 정렬된 두 배열을 포인터를 이용해 병합. 불필요한 쌍방 비교를 생략하나 추가 메모리 배열 필요. |
| **Heap Sort** | $O(N \log N)$ | $O(N \log N)$ | $O(1)$ | Max-Heap의 루트(최댓값)를 반복 추출하여 뒤에서부터 채움. 추가 메모리는 없으나 캐시 효율이 떨어짐. |
